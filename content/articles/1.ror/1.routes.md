#### 📌 Qu'est-ce que le Routage dans Rails ?

Le routage dans Rails, c'est ce qui relie vos URLs aux actions de vos contrôleurs. 

Par exemple, une requête GET vers /articles pourrait être dirigée vers l'action index dans le contrôleur Articles (*ArticlesController#index*). 

C’est dans le fichier **config/routes.rb** que tout cela est configuré. 

Chaque route correspond à un petit ensemble : un verbe HTTP (comme GET, POST, PATCH ou DELETE), un modèle d’URL, une action spécifique dans le contrôleur, et parfois des contraintes ou des helpers pour simplifier l’utilisation des routes.


#### 🗺️ Définitions de Base des Itinéraires

Voici une petite explication pour mieux comprendre comment définir des routes dans votre application Rails :

1. Syntaxe Standard

Pour faire simple, si vous voulez que lorsqu’on accède à l’URL `/welcome/index`, cela lance la méthode `index` dans le contrôleur `Welcome`, vous pouvez écrire :  

```ruby [config/routes.rb]
get 'welcome/index'
```
  
Cela dit à Rails : “Lorsque quelqu’un va sur */welcome/index*, montre le contenu de la méthode *index* du contrôleur *Welcome*.”


2. Route Racine

Pour que la page d’accueil de votre site soit par exemple la page `home#index`, il suffit d’écrire :  

```ruby [config/routes.rb]
root 'home#index'
```

Et voilà, votre site affiche cette page dès qu’on arrive à la racine !

3. Routes Nomées

C’est pratique si vous souhaitez donner un nom plus sympa à une route. Par exemple, si vous voulez que l’URL */about* mène à la page dédiée, et que vous pouvez utiliser un helper pratique comme *about_page_path*, écrivez :  

```ruby [config/routes.rb]
get 'about', to: 'pages#about', as: 'about_page'
```

Du coup, dans votre code, vous pouvez écrire *about_page_path* pour générer cette URL facilement.

4. Routes RESTful avec `resources` :

Rails favorise une façon naturelle de gérer les ressources via REST. En tapant simplement :  

```ruby [config/routes.rb]
resources :articles
```

Rails va automatiquement créer tout un ensemble d’itinéraires pour faire :  
- voir la liste des articles (`index`)  
- voir un article précis (`show`)  
- créer un nouvel article (`new`, `create`)  
- modifier un article (`edit`, `update`)  
- supprimer un article (`destroy`)  


Si vous souhaitez limiter cet ensemble à seulement quelques actions, vous pouvez préciser :  

```ruby [config/routes.rb]
resources :articles, only: [:index, :show]
```


Ou si vous voulez exclure quelques actions, par exemple la suppression, vous pouvez écrire :  

```ruby [config/routes.rb]
resources :articles, except: [:destroy]
```

##### 🗺️ Itinéraires de Ressources Nommées

Utiles lorsque vous avez des modèles avec des relations hiérarchiques (par exemple, articles et commentaires) :

```ruby [config/routes.rb]
resources :articles do
  resources :comments
end
```

Cela génère des itinéraires comme :

```ruby [bash]
/articles/:article_id/comments
/articles/:article_id/comments/:id
```

Pour éviter un enchevêtrement profond, limitez-vous à une seule couche pour plus de clarté et de maintenabilité.


##### 🗺️ Itinéraires Membres vs Collection

Vous avez la possibilité de définir des actions personnalisées aussi bien sur des éléments individuels (membres) que sur l'ensemble de la collection.

Voici un exemple pour mieux comprendre :

```ruby [config/routes.rb]
resources :articles do
  member do
    get 'preview'
  end

  collection do
    get 'archived'
  end
end
```


L’itinéraire pour un membre spécifique sera par exemple : */articles/:id/preview*, tandis que celui pour toute la collection sera : */articles/archived*.


##### 🏷️ Espaces de Noms et Routage

Les espaces de noms, c'est super pratique pour organiser tout ça, surtout quand il s'agit des panneaux d'administration ou des API. 

Ça permet de garder les contrôleurs bien rangés et de structurer les routes en toute simplicité.

Par exemple, pour l'espace admin, vous pouvez faire comme ceci :

```ruby [config/routes.rb]
namespace :admin do
  resources :users
end
```

Ça correspond à un contrôleur appelé `Admin::UsersController` et ça crée des itinéraires comme `/admin/users`, pratique non ?

Et pour les APIs, c'est pareil : vous pouvez imbriquer les namespaces afin de bien structurer tout votre API, comme ici :


```ruby [config/routes.rb]
namespace :api do
  namespace :v1 do
    resources :products
  end
end
```


Ainsi, vos routes seront toutes bien organisées, par exemple `/api/v1/products`. C'est simple, efficace et ça facilite la maintenance !


##### 🔀 Routage Superficiel

Le routage en profondeur peut parfois devenir un peu compliqué. Pour simplifier la gestion des URLs, optez pour le routage superficiel ! voici comment faire !  

```ruby [config/routes.rb]
resources :articles do
  resources :comments, shallow: true
end
```

Grâce à cette configuration, les chemins générés seront plus simples :

```ruby [bash]
/articles/:article_id/comments # pour index, create
/comments/:id # pour show, edit, update, destroy
```


##### ⚠️ Contraintes et Conditions de Route Personnalisées

Vous pouvez limiter les itinéraires selon certains paramètres ou conditions, comme par exemple :

en utilisant *constraints* :

```ruby [config/routes.rb]
get 'photos/:id', to: 'photos#show', constraints: { id: /\d+/ }
```


ou avec le routage basé sur le sous-domaine :

```ruby [config/routes.rb]
constraints subdomain: 'admin' do
  get '/', to: 'admin/dashboard#index'
end
```

##### 📏 Préoccupations pour un Routage DRY

N'hésitez pas à utiliser *concerns* pour réutiliser facilement les définitions d'itinéraires, comme ici :  

```ruby [config/routes.rb]
concern :commentable do
  resources :comments
end

resources :articles, concerns: :commentable   
resources :photos, concerns: :commentable
```

##### 📂 Organisation des routes

Pour rendre notre code plus clair et organisé, on va créer un petit initializer qui va nous permettre d’interpréter facilement nos fichiers de routes modulares, situés dans *config/routes/*.  

Voici comment faire :  

```ruby [config/initializers/routes_draw.rb]
class ActionDispatch::Routing::Mapper
  def draw(routes_name)
    path = Rails.root.join("config/routes/#{routes_name}.rb")
    
    raise ArgumentError, "Fichier manquant: #{path}" unless File.exist?(path)
    
    instance_eval(path.read, path.to_s)
  end
end
```

Ce système permet de mieux séparer les responsabilités :  
- *routes.rb* sert à déclarer nos routes globales,  
- le fichier dans *initializers/* se charge d’étendre la classe Mapper pour charger nos routes modulaires.  

Par exemple, dans *config/routes.rb*, on peut faire appel à notre méthode `draw` comme ceci :  


```ruby [config/routes.rb]
Rails.application.routes.draw do
  ...
  
  draw :users

  ...
end
```

Et pour illustrer la structure d’un fichier de routes modulaire, voici un exemple dans *config/routes/users.rb* :  

```ruby [config/routes/users.rb]
# /users
namespace :users do
  # /profiles
  get   '/profiles',               to: 'profiles#index'
  get   '/profiles/list',          to: 'profiles#list'
  get   '/profiles/:profile_id',   to: 'profiles#show'
  post  '/profiles',               to: 'profiles#save'
  get   '/profiles/show-avatar',   to: 'profiles#show_avatar'
  post  '/profiles/upload-avatar', to: 'profiles#upload_avatar'

  # /groups
  resources :groups
  post '/groups/:group_id/add-member',     to: 'groups#add_member'
  post '/groups/:group_id/remove-member',  to: 'groups#remove_member'
end
```


##### ↪️ Redirections et Paramètres par Défaut

Voici comment rediriger un itinéraire vers un autre :  

```ruby [config/routes.rb]
get '/home', to: redirect('/')
```

Et si vous souhaitez définir des paramètres par défaut, c’est par ici :  

```ruby [config/routes.rb]
get 'posts/:id', to: 'posts#show', defaults: { format: :json }
```

##### 🛑 Erreurs de Routage et Débogage

Utilisez rails routes ou bin/rails routes pour voir tous les itinéraires définis.

Flags utiles :

```ruby [bash]
rails routes | grep articles
```

##### 📋 Résumé

Le routage dans la version actuelle de Ruby on Rails est super flexible, puissant et vraiment clair à utiliser.  

En maîtrisant le routage, vous pouvez créer des applications web plus expressives, faciles à maintenir et qui évoluent sans souci.  

Que ce soit pour définir des itinéraires simples pour vos ressources ou pour construire une API complexe, Rails offre tous les outils dont vous avez besoin pour le faire de manière propre et efficace.
