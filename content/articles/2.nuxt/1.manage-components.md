#### 📌 Comment gérer les composants d'une application Nuxt ?

À mesure que votre application Nuxt devient plus grande, vous pourriez commencer à trouver certaines conventions de Nuxt et Vue un peu frustrantes. 

Voici ma façon préférée d’organiser les composants quand on travaille sur des projets de grande envergure. 

Oui, cela peut dévier un peu des « bonnes pratiques » habituelles, mais c’est souvent plus pratique !


#### 📂 Dossiers de composants locaux

J’aime avoir tout ce dont j’ai besoin à portée de main quand je travaille sur une tâche. 

C’est pour ça que j’aime beaucoup les composants monofichiers (ou SFC). 

Je ressens la même chose pour les pages.  

Si j’ai des petits morceaux de code que je n’utilise que pour une seule page, je préfère les mettre dans un sous-dossier dédié à cette page. 

Comme ça, je n’ai pas à chercher partout.  

Ça m’aide aussi à ne pas avoir à déchiffrer toute l’organisation des dossiers chaque fois que je dois faire une modification.


#### 📂 Le dossier components/ devient alors celui des composants globaux

Dans l'exemple ci-dessous, on suppose que les composants Gallery sont propres à la page produit. 

Si jamais vous en avez besoin sur une autre page, il faudra simplement les déplacer dans l’ancien dossier components/. 

Gardez en tête que ce dossier doit être réservé aux composants qui sont utilisés sur plusieurs pages ou qui ne sont liés à aucune page spécifique, comme par exemple des modales globales.


```bash
/components             // for global components only
/pages
  /home                 // the homepage
    /components         // components for the homepage
      /Banner.vue
    /index.vue           // the home page
  /product
    /components         // components for the product page
      /Reviews.vue      // files are single words if possible
      /Gallery          // larger components can have their own children
        /index.vue      // the main Gallery container
        /ImageList.vue  // more components used in the Gallery component
    /index.vue          // the product page
```

#### 📄 Des noms de fichiers courts et simples

Dans le guide de style de Vue, il est recommandé que les singletons commencent par The et que tout autre composant ait un nom composé de deux mots, comme ToDoList.vue ou ToDoItem.vue.


Je trouve cela plutôt agaçant. Est-ce que vous avez vraiment envie d’écrire ProductReview, ProductGallery, ProductDetails encore et encore jusqu’à la fin de votre vie ?


Pas moi. Je sais que cette convention est censée réduire les conflits de noms, mais honnêtement, en pratique, je n’ai jamais eu le moindre problème avec ça.

#### ⚙️ Mise en place

- Dire à Nuxt de ne pas traiter les composants comme des pages

Pour que Nuxt ne considère pas certains composants comme des pages, il suffit de lui dire d’ignorer les dossiers components qui se trouvent à l’intérieur du dossier pages. 

Étant donné que ce dernier a une importance particulière dans Nuxt, il est utile de préciser de ne pas tenir compte de ces sous-dossiers lors de la création des routes, afin d’éviter toute confusion ou comportement inattendu.

```js [nuxt.conf.ts]
pages: {
  pattern: ['**/*.vue', '!**/components/**']
},

// Nuxt 3.15.4 and older
hooks: {
  'pages:extend'(pages) {
    const pagesToRemove: NuxtPage[] = []
    pages.forEach((page) => {
      if (page.path.includes('component')) pagesToRemove.push(page)
    })

    pagesToRemove.forEach((page: NuxtPage) => {
      pages.splice(pages.indexOf(page), 1)
    })
  }
}
```

- Ajouter les sous-dossiers aux imports automatiques

Si vous utilisez les composants importés automatiquement, pensez à dire à Nuxt qu'il doit aussi regarder dans le dossier pages pour y dénicher d'autres composants.

```js 
components: [
  '~/components', {
    path: '~/pages',
    pattern: '**/components/**',
    pathPrefix: false
  }
]
```

- Déplacer aussi votre page d’accueil

Pour garder tout bien organisé, vous pouvez même déplacer votre page d'accueil dans un sous-dossier à l'intérieur du dossier pages ! 

C'est super simple : il suffit simplement d'utiliser le composable definePageMeta pour indiquer le chemin de la route.


```js
<template>
  <div>My Homepage</div>
</template>
<script setup>
  definePageMeta({
    path: '/',
  })
</script>
```

#### 📋 Résumé


Adopter une organisation où chaque page possède ses propres composants tout en conservant un dossier global pour ceux qui peuvent être réutilisés, c’est une bonne idée pour garder le projet clair, modulaire et efficace. 


Cela évite de se perdre dans des déplacements inutiles dans l’arborescence, facilite le travail en équipe et rend la maintenance des composants plus simple sur la durée.
