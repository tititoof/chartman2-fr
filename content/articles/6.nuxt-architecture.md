# Architecture Nuxt 3 : Guide Pratique

Nuxt 3 adopte une architecture modulaire et stricte basée sur les principes de l'architecture de l'application. Voici les couches principales et leurs responsabilités :

## 1. Couches Principales

### 📁 `components/`
- **Rôle** : Composants réutilisables (Vue 3 composants)
- **Convention** : PascalCase
- **Exemple** : `components/MyButton.vue`

### 🧠 `composables/`
- **Rôle** : Logique métier réutilisable (composables)
- **Convention** : PascalCase
- **Exemple** : `composables/useUser.ts`

### 🧩 `layouts/`
- **Rôle** : Maquettes partagées (Vue 3 layouts)
- **Convention** : PascalCase
- **Exemple** : `layouts/DefaultLayout.vue`

### 📄 `pages/`
- **Rôle** : Routes dynamiques (Vue Router)
- **Convention** : PascalCase
- **Exemple** : `pages/index.vue` (route `/`)

### 🧾 `server/`
- **Rôle** : API backend (Fastify, Express, etc.)
- **Exemple** : `server/api/users.get.ts` (route `/api/users`)

### 📜 `types/`
- **Rôle** : Définitions de types (TypeScript)
- **Exemple** : `types/user.d.ts`

### 🧹 `utils/`
- **Rôle** : Fonctions utilitaires (non réutilisables)
- **Exemple** : `utils/formatDate.ts`

## 2. Bonnes Pratiques

### ✅ Séparation des responsabilités
- **Composables** : Logique métier (ex : `useAuth()`) ✅
- **Stores** : États globaux (ex : `useUserStore()`) ✅
- **Components** : UI (ex : `MyButton.vue`) ✅

### ⚠️ Interdits
- **Pas de service locator** : Utilisez des composables au lieu de `provide/inject`
- **Pas de logique dans les templates** : Déplacez-la vers les composables

## 3. Exemple de Structure
```
project-root/
├── components/
│   └── MyButton.vue
├── composables/
│   └── useUser.ts
├── layouts/
│   └── DefaultLayout.vue
├── pages/
│   └── index.vue
├── server/
│   └── api/
│       └── users.get.ts
├── types/
│   └── user.d.ts
└── utils/
    └── formatDate.ts
```

## 4. Tests
- **Composables** : Unit tests avec Vitest
- **API** : Tests E2E avec Cypress ou Playwright
- **UI** : Tests visuels avec Cypress + Puppeteer

## 5. Performance
- **Lazy loading** : Utilisez `defineAsyncComponent`
- **SSG** : Priorisez le rendu statique pour les pages statiques
- **Hydratation** : Optimisez le rendu côté client

## 6. Sécurité
- **Validation côté serveur** : Utilisez `@nuxtjs/validator`
- **Type safety** : Utilisez TypeScript pour éviter les erreurs de type
- **Authentification** : Implémentez un middleware d'authentification
